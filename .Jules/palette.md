## 2023-10-27 - [Accessibility] ARIA labels for numeric inputs and alert roles for dynamically injected UI elements
**Learning:** When inputs lack an explicitly bound `<label>` element with a matching `for` attribute (e.g., when the text label actually wraps a checkbox instead of the input), screen readers will announce them as generic text fields. Explicit `aria-label`s must be added. In addition, dynamically injected inline validation error messages need `role="alert"` (and optionally `aria-live="assertive"`) so that screen readers announce the error immediately when it appears, instead of relying on the user to navigate to it.
**Action:** When adding inputs with complex visual relationships to labels (like adjacent checkboxes), always explicitly specify an `aria-label` for screen reader clarity. Whenever an error message is toggled or updated dynamically in the DOM without a page reload, use `role="alert"` on the error container element.
